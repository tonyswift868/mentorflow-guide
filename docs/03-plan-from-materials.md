# 专题：从一摞资料到一张能照着学的计划

事实基线：`e61fd00d`。本篇按当前项目代码和需求状态说明；“常被问／偶尔问／基本不问”是面试复习优先级，不是面试频率统计。

想象你要替朋友安排一门“从没下过厨，到能独立做一道菜”的短课：先问他想做到什么、现在会什么、哪天有空；再挑菜谱；然后把章节排成课；最后把每次练习放进日历。这个比喻帮助理解计划流程，不表示软件真的在教做菜，也不表示 AI 可以凭空编菜谱。

## 1. 先问清楚想学到哪里｜常被问

用户先定目标，再排计划。

计划先问清楚学什么、学到什么程度，以及能投入多少时间。表单收集学习目标、最终目标、当前水平、开始和结束日期、每天上限、每周可学日、特殊日期和补充说明；程序校验必填内容、日期和权重，格式不合就要求修正。 **一句话层。**

像给朋友排厨艺课，先问想做什么菜、现在会哪些刀工、哪天能来。AI 帮忙理解补充要求、追问缺少的信息，并给一份需求摘要和大致模块。用户确认前，不直接生成完整知识地图；本机控制流程的程序按阶段执行，付费生成和开始计划也由用户点按钮确认。 **三句话层。**

这和“一句话让模型一次做完整个课表”不同：先有需求摘要，再有粗略模块；用户确认方向后才进入资料选择，之后再看按资料整理的结构。 **深一层。**

### 为什么不直接让 AI 一次生成完整计划？

- 表单收集学习目标、最终目标、当前水平、开始和结束日期、每天上限、每周可学日、特殊日期和补充说明；程序校验必填内容、日期和权重，格式不合就要求修正。
- AI 帮忙理解补充要求、追问缺少的信息，并给一份需求摘要和大致模块。
- 用户确认前，不直接生成完整知识地图；本机控制流程的程序按阶段执行，付费生成和开始计划也由用户点按钮确认。

### 学习路线：你可以这样跟面试官说

我会先把目标、基础和时间约束问清，再让用户确认学习方向。AI 帮忙理解和整理，程序控制流程并校验输入，不会把一条模糊指令直接变成整份计划。
## 2. 先挑完整资料，再把正文请进来｜常被问

采用资料后才读取正文。

推荐资料只是候选，不代表正文已读取或覆盖已确认。AI 推荐完整资料，例如教材、课程、完整文档或 GitHub 文字仓库；它给出名称、链接、简短理由和大致覆盖模块。 **一句话层。**

朋友挑菜谱时可以用自己带来的书，也可以从推荐书单里选。用户上传文件、贴网址或给 GitHub 仓库后，资料进入本机计划。被采用的网页或文件再被读取、抽出正文并切成带章节位置的文字块，后面的知识地图从这些已采用的文字块出发。 **三句话层。**

用户自己的资料默认采用；推荐资料由用户选择后读取。用户采用后，资料才加入计划用于教学；读取失败会显示原因，不会把“推荐了”说成“已读完”。 **深一层。**

### 用户点了“采用”，是不是代表程序已经确认这份资料适合学习？

- AI 推荐完整资料，例如教材、课程、完整文档或 GitHub 文字仓库；它给出名称、链接、简短理由和大致覆盖模块。
- 用户上传文件、贴网址或给 GitHub 仓库后，资料进入本机计划。
- 用户自己的资料默认采用；推荐资料由用户选择后读取。

### 学习路线：你可以这样跟面试官说

资料推荐只是候选。用户选中后，程序才读取正文并保存章节和文字块；自己的资料按产品规则默认采用。这样知识地图有实际原文可追，而不是按资料标题猜课程内容。
## 3. 先看资料目录，再画路线图｜常被问

用户先看目录，再定范围。

先让用户看资料目录和覆盖范围，再确认要学的路线。系统把原文标题、层级和段落整理成目录视图，展示大致模块、资料覆盖和目标中的资料缺口。 **一句话层。**

这像先翻菜谱目录，看看课程应该有“备料、火候、调味”哪些课，再问朋友是否符合目标。用户确认后，程序才把已确认模块对应的正文片段交给后续知识地图。结构由本机控制流程的程序按用户选定章节范围组装，不是让模型从空白写一整张地图。 **三句话层。**

用户可以先调整范围再确认；后续知识地图只使用采用资料和已确认模块对应的原文块。 **深一层。**

### 为什么先看大致模块，不直接生成知识点？

- 系统把原文标题、层级和段落整理成目录视图，展示大致模块、资料覆盖和目标中的资料缺口。
- 用户确认后，程序才把已确认模块对应的正文片段交给后续知识地图。
- 结构由本机控制流程的程序按用户选定章节范围组装，不是让模型从空白写一整张地图。

### 学习路线：你可以这样跟面试官说

我把“学什么范围”先交给用户确认，再基于确认过的资料章节整理知识地图。这样模型不能悄悄扩大学习范围，用户也能在投入更多生成前看到路线。
## 4. 知识结构与参考资料的分工｜常被问

知识正文成课，导航作参考。

资料目录不是课程本身，书单和路线可留作导航，不必变成要讲、要考的知识点。 **一句话层。**

书单、学习路线和资料取舍可以放在模块开头当“资料导航”，而不变成要讲、要考、要记时长的知识点。

这像把菜谱书的“推荐书目”放到课前参考架，而不是安排成一节“学习书单”。明确是书单或路线的章节先由程序识别；看不清用途的章节，AI 按给定段落把每段标成“知识”或“导航”。程序核对段落编号没有遗漏或重复，再根据原文标题层级生成知识结构和出处。 **三句话层。**

用户定的是大知识点按主题组织，大小由主题决定，不设上下限、不按字数或分钟机械切；这一要求目前落实在已有计划的主题重组流程中，模型提议分组、程序检查覆盖。新建计划的目录流程仍从原文层级构造初始结构。两条路径不同；重组后小要点可能换父点并重新编号。 **深一层。**

新式知识点里，大点有若干小要点；每条讲义摘句带着对应原文出处，原文仍可点开。若资料本身没有知识正文、只有导航内容，计划不会用导航硬凑出一门课。

### 资料导航和知识点有什么区别？

- 书单、学习路线和资料取舍可以放在模块开头当“资料导航”，而不变成要讲、要考、要记时长的知识点。
- 明确是书单或路线的章节先由程序识别；看不清用途的章节，AI 按给定段落把每段标成“知识”或“导航”。
- 每条讲义摘句带着对应原文出处，原文仍可点开。
- 新建计划的目录流程仍从原文层级构造初始结构。

### 学习路线：你可以这样跟面试官说

目录只是材料的组织方式，不是现成课程。系统会把参考导航和可教正文分开；用户希望知识点按主题连贯组织，但我会区分初始建图和旧计划重组，不把一条路径说成另一条。
## 5. 估时不是拍脑袋，日历也不是番茄钟｜常被问

程序按学习内容估时。

时长从学习内容和检测需求估算，再按可学日排进计划，不是先拍个总数。 **一句话层。**

像把菜谱步骤、练习和可上课的日期放进日历。旧式知识点估算可参考原文长度、题量与难度标记，由程序计算分钟数；AI 不直接决定分钟数。新式知识点初建时，小要点分钟由程序按原文量和默认难度计算，大点总时长等于小要点之和；当前新建路径不另跑一次 AI 难度评估。 **三句话层。**

计划把分钟数按可学日分配，周几不学可设为 0，半天可设为 0.5，特殊日也能覆盖周安排。没完成的分钟变成待还，后来学习先补欠账；学多了显示超前。用户可以调整日期、每日上限或内容。 **深一层。**

### 谁来估时，漏学之后怎么办？

- 旧式知识点估算可参考原文长度、题量与难度标记，由程序计算分钟数；AI 不直接决定分钟数。
- 新式知识点初建时，小要点分钟由程序按原文量和默认难度计算，大点总时长等于小要点之和；当前新建路径不另跑一次 AI 难度评估。
- 周几不学可设为 0，半天可设为 0.5，特殊日也能覆盖周安排。
- 没完成的分钟变成待还，后来学习先补欠账；学多了显示超前。

### 学习路线：你可以这样跟面试官说

时长估算有明确输入：原文、题目和难度；程序负责计算与日历分配。学习进度不足会显示待还，后面先补欠账，用户决定是否重排，不会暗中改掉计划。
## 6. 提示词和上下文：把当前资料交给 AI，把流程留给程序｜常被问

模型只处理当前步骤的信息。

提示词就是给 AI 的任务说明；上下文是这次要看的原文、目标和相关资料。请求只带完成当前任务所需的内容和明确编号，不把整本书塞进去。目录分类请求以章节 ID、标题和段落为输入；知识点讲义请求只带相关知识点、小要点及其出处段落。 **一句话层。**

像给助教本周菜谱和今天要做的一步，而不是搬来整座图书馆。对用途含混的章节，AI 按批次把给定段落标成“知识”或“导航”。程序检查编号覆盖没有遗漏或重复。讲义生成也按小批次提供对应原文，返回内容要能在原文里核实。 **三句话层。**

这些请求不是让 AI 自由发挥：分类器拿到章节 ID、标题和原文段落；讲义请求只带点与小要点的 ID 以及引用段落。有效讲义必须是对应段落中的原文摘句，并通过来源校验；失败的摘句只在其批次内重试。

“前缀”就是请求开头的内容；缓存是复用此前完全相同的开头。项目的请求布局缓存是进程内、有界、按相同系统提示和前缀追加历史；它不是持久学习记录，也不保证每次命中。 **深一层。**

### 如何让 AI 看材料，但不把系统流程交给它？

- 目录分类请求以章节 ID、标题和段落为输入；知识点讲义请求只带相关知识点、小要点及其出处段落。
- 程序检查编号覆盖没有遗漏或重复。
- 有效讲义必须是对应段落中的原文摘句，并通过来源校验；失败的摘句只在其批次内重试。
- “前缀”就是请求开头的内容；缓存是复用此前完全相同的开头。
- 项目的请求布局缓存是进程内、有界、按相同系统提示和前缀追加历史；它不是持久学习记录，也不保证每次命中。

### 学习路线：你可以这样跟面试官说

AI 只处理本次要看的段落和清楚的任务；程序检查编号、原文出处与流程状态。把稳定内容放前面能争取缓存复用，但命中与否要看实际请求。
## 学习路线：不用背｜基本不问

不用背计划草稿的每个阶段名、SQLite 表名、资料编号别名、缓存页上限或分钟公式的参数；能说清目标如何变成原文支撑的课程、AI 和程序各自做什么、以及欠账怎样显示，就足够了。
