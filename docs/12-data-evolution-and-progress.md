# 13｜数据升级：保留旧计划和真实进度

## Q18｜升级数据结构并保留进度｜讲清原理

数据库结构会随软件演进，比如增加一张表或扩展答案字段。升级迁移就是把旧结构逐步转换成新结构的程序。它必须保留旧记录原本表达的意思；字段不存在，不代表可以随意补造一条“用户已完成”的事实。MentorFlow 的本地课程库有 schema 版本，打开时在事务中按版本逐级迁移；高于当前程序认识的版本则拒绝打开，避免旧代码把新数据写坏。

举个例子：项目曾把旧题格式迁到新版本时，保留计划、知识点、学习进度和已过检测；旧题本身仍留存，但不再进入当前考核，受影响模块重新备题。历史答案也不会被迁移程序伪装成学生的新选择。这是“保留旧数据”与“让旧结构继续适用”两件事：前者保留事实，后者可以调整后续使用规则。

本机课程库迁移和服务器数据库迁移也要区分。服务器当前 PostgreSQL 已迁到 0045，回退 Java 镜像不会自动倒回数据库；数据库快照恢复可能覆盖切换后新写的数据。因此，版本升级和恢复要核对代码版本、数据库版本及其兼容关系。不能把“停着旧 Python 服务”说成“旧服务保证能接管当前数据库”。

**可以直接这样说：**“升级数据结构时，目标是保留用户已有计划、进度和历史事实，再用按版本执行的事务迁移补新结构。比如旧题可以退出当前考核，但原计划和已过检测仍保留。代码回退也不等于数据库回退，所以恢复前要在用户数据只读副本上验证迁移，并检查历史记录是否完整。”

### 升级本地数据结构时，怎样保住旧计划与进度？

- 按 schema 版本逐级运行事务迁移；遇到比程序更新的版本就拒绝打开，避免旧结构误写。
- 迁移保留旧计划、知识点、学习进度和已过检测；不适用的旧题可退出当前考核，但不能删除历史事实或补造答案。
- 只读打开原库制作隔离副本，在副本上运行迁移并核对历史计划、进度、测评与答案是否保留。

### 追问加练

面试官追问：“旧题不再用于当前考核，算不算丢数据？”答：“不算，题目和历史事实保留，只调整它是否进入当前考核。”
