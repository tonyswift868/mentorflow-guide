# 14｜登录故障复盘与个人贡献

## Q19｜切到 Java 后登录失败｜必须能背

### 前置：一条连接可以分成两段

HTTPS 可以理解为带加密保护的 HTTP。**入口代理**先接到客户端请求，再把请求交给真正处理业务的程序；本项目入口是 nginx，业务程序是 Java 服务。**TLS 终止**指入口完成外侧加密连接，后面另一段连接可以在内部网络使用 HTTP。外侧 HTTPS 与内部 HTTP 可以同时成立，不是用户突然取消了加密。

`X-Forwarded-Proto` 是入口交给后端的一个请求头，告诉后端原先那段请求使用什么协议。例如值为 `https`，意思是客户端到入口走 HTTPS。它描述原始请求，不会把内部 HTTP 字节重新加密。

### 讲解：服务健康，不等于登录链路正确

这次迁移的故障发生在切流后：客户端密码登录和刷新都表现为账号服务不可用。原因不在密码内容，而在 Java 看到了哪一段协议。入口已经结束 TLS，再用内部 HTTP 转给 Java；当时 Java 没按转发头恢复原请求协议，原生认证检查把它当成非 HTTPS，返回 `403 NATIVE_TRANSPORT_REQUIRED`。客户端将未识别的错误映射成 `NATIVE_AUTH_UNAVAILABLE`，用户看到的便是登录失败。

可以沿请求画两段线：`客户端 —HTTPS→ 入口 —HTTP→ Java`。只看 Java 接到的后一段，会误以为用户使用了不安全连接；把入口提供的原始协议信息恢复到请求对象，认证检查才会按外侧 HTTPS 判断。修复采用 Spring 的 `server.forward-headers-strategy=framework` 配置，没有删除认证对安全连接的要求。

为什么切换前没发现？此前对照主要验证直接连接的接口行为，缺少“真实客户端经过 TLS 入口再到 HTTP 后端”的组合。后来在本机用旧配置复现登录和刷新失败，用修后配置跑真实客户端的完整链路，并验证没有转发信息的直接 HTTP 仍会被拒绝。项目记录随后确认重新切到 Java 后，用户自动登录、同步和上课正常。

这个故事该背的是**现象→缺失的链路信息→修复→如何验证**。不要扩成十个不相干的BUG，也不要说成“在线上日志亲眼看到了原始403”：当时没有保存完整原始响应，原因有代码、配置、本机修前/修后和重新切换结果支持。

### 可以直接这样说

“入口接的是 HTTPS，转给 Java 的内部连接却是 HTTP。Java 当时没有按转发头恢复原始协议，原生认证误把请求当成不安全连接并拒绝。客户端又把这个未识别的错误显示成账号服务不可用，因此密码正确也无法正常登录或刷新。”

### Java 切换后，为什么客户端原生登录会失败？

- 入口终止外侧 HTTPS，向 Java 转发的内部请求是 HTTP。
- Java 当时没有按转发头恢复原协议，认证检查误判请求非 HTTPS并拒绝。
- 客户端把该未识别的错误显示为 NATIVE_AUTH_UNAVAILABLE，所以用户看到账号服务不可用。

### 追问加练

面试官可能追问：“怎样修复，并确认没有放过真正的不安全请求？”

一句话答法：配置Spring读取转发头，跑真实客户端经过代理的修前、修后验证，并确认没有转发信息的直接HTTP仍被拒绝，保留原来的HTTPS检查。
## Q20｜个人职责与验证证据｜必须能背

### 前置：产品做了什么，和你做了什么不同

**项目能力**说的是整套软件能完成什么；**个人贡献**说的是你实际决定、实现或验证了其中哪部分。借助框架、开源库或 AI 工具，不等于没有贡献，也不等于可以把所有产出都说成独立手写。要把自己的职责和采用的工具分别说清楚。

### 讲解：选一项真实参与，讲到能核对

MentorFlow 采用 AI 协作开发，项目里的产品规则和验证来自明确的用户需求与任务。比如“题只从原文找、问答由用户看答案勾要点”，是产品选择；落实到资料、出题流程和实际软件操作，才成为可检查的行为。面试讲贡献时，可以按自己的实际参与，选需求取舍、某个实现模块或某项测试中的一项，说清输入、决定和结果。

一个可核对的例子是本文这套资料：先发现身份权限题混入回退答案，再追到原文题块和程序全选规则；重写后还要用真实导入流程检查，确认参考要点仍只回答本题。这说明“怎么证明做对”，不代表每位阅读者都亲自完成了所有步骤。没有做过源码改动的人，不应把这段讲成自己写了全部认证服务。

现场回答时，先说自己实际承担的边界，再举一个能展示的产物：一段亲自改过的逻辑、一组自己核对过的测试，或一次真实软件反馈。不要用团队总代码行数代替个人贡献；也不要用“AI写的”跳过为什么采用、怎样审查和哪里还没验证。

### 可以直接这样说

“这套项目用了 AI 协作开发，我会把个人职责和工具产出分开讲。我实际参与的部分，要能说明自己作了什么决定、核对了什么结果；采用现成实现的地方就如实说明。比如用户反馈和一次真实回归，可以支持我讲清一个问题，不能据此声称全部代码都是独立手写。”

练习时再口述一项**自己真正做过**的例子。这里不预填虚构的个人经历，也不要求把示范故事冒认成自己的实现工作。

### 怎样把自己在 MentorFlow 中的贡献说清楚？

- 区分整套项目能力与自己实际负责、决定或核对的部分。
- 如实说明采用的框架、现成实现和 AI 协作，不把它们冒称全部独立手写。
- 用实际参与的产物、问题与验证结果支持自己的职责描述。

### 追问加练

面试官可能追问：“如果主要靠 AI 写码，你怎么证明自己理解项目？”

一句话答法：选自己真正参与的一条流程，讲清为什么这样设计、出错怎样定位，以及拿什么结果确认有效。
