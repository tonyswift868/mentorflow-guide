# 专题：两台电脑怎样接上同一份学习账

面试频率是本课的学习优先级判断，不是统计调查。事实按基线 `e61fd00d` 核对；先用一句话讲通，再练完整流程，最后看冲突与失败边界。

## 1. 同步的范围与边界｜常被问

同步让同一账号能换电脑继续学习。 **一句话层。**

用户登录另一台电脑后，客户端会同步计划、进度、作答记录、报告、闲聊和上课位置。 两台设备各有自己的本地学习库，再通过服务器交换记录。 用户上传文件的原件、Live2D 模型和朗读引擎等大文件不上传；正文可以同步，所以另一台电脑能继续依据文字学习，若要看原始排版而本机没有原件，软件会提示原件在另一台电脑。 **三句话层。**

把它想成两间分馆共用一套读者借阅账：每间馆有自己的柜台和本地账本，定时把新增或变更的账目交给中央档案室，再取回另一间馆的记录。这个比喻能说明“本地保存、服务器中转”，但学习数据不是一本整库文件来回复制；系统按记录和字段处理变化，原始上传文件也不在服务器档案室里。 **深一层。**

### 换一台电脑后，哪些学习内容能接着用？

- 用户登录另一台电脑后，客户端会同步计划、进度、作答记录、报告、闲聊和上课位置。
- 两台设备各有自己的本地学习库，再通过服务器交换记录。
- 用户上传文件的原件、Live2D 模型和朗读引擎等大文件不上传；正文可以同步，所以另一台电脑能继续依据文字学习，若要看原始排版而本机没有原件，软件会提示原件在另一台电脑。
## 2. 客户端编排与 Java 服务分工｜偶尔问

客户端编排同步，Java 服务保存记录。 **一句话层。**

客户端的同步服务在账号登录后启动，在退出时停止；课程同步器按本地记录类型、编号和载荷生成网络记录，并维护增量游标。 Java 服务提供写单条、删单条、批量写入、读取快照和读取增量变化的接口。 它在请求中取得用户和组织空间身份，再由仓库层处理数据库事务。 **三句话层。**

分馆的柜台负责整理账单和递送，中央档案室负责核实是谁递来的、写进哪一份账。这能说明职责分工；它不表示服务器能直接打开客户端 SQLite，也不表示客户端把整个数据库文件上传。 **深一层。**

### 客户端和 Java 同步服务各负责什么？

- 客户端的同步服务在账号登录后启动，在退出时停止；课程同步器按本地记录类型、编号和载荷生成网络记录，并维护增量游标。
- Java 服务提供写单条、删单条、批量写入、读取快照和读取增量变化的接口。
- 它在请求中取得用户和组织空间身份，再由仓库层处理数据库事务。
## 3. 增量同步：先拉变化，再传本机记录｜常被问

同步先拉变化，再传本机记录。 **一句话层。**

客户端先带着上次保存的游标读取变更；服务器按游标分页返回记录，客户端把远端记录交给本地存储合并，再保存新的游标。游标像中央账本上的阅读书签，说明“上次读到哪里”；增量就是书签后新增的变化。 接着客户端读取本机待上传队列，优先把记录分批提交；较新的服务器支持批量接口，旧服务返回 404 或 405 时，客户端会退回逐条接口。 **三句话层。**

服务端每条写入带预期修订号和请求编号：修订号用于判断两边是否基于同一版本，请求编号用于识别重试请求。比如两次都想改第 7 版，一次先改成第 8 版后，另一次就会收到版本冲突，这叫乐观并发控制；同一编号和内容重发会拿回原回执，避免“写成功但回信丢了”造成重复写入，这叫幂等。Java 服务把一批写入放在一个外层事务里，每条记录用保存点隔开；单条冲突可以单独返回，数据库或未处理异常会让外层事务回滚。 **深一层。**

想成两间分馆先取中央档案室的“最近变更清单”，再交自己柜台的新账。批量接口像一只大信封，单条接口像一张张递送；这只是解释传输顺序，真实协议还会核对账号空间、修订号和请求回执。

### 一轮增量同步怎样走完，两个编号有什么用？

- 客户端先带着上次保存的游标读取变更；服务器按游标分页返回记录，客户端把远端记录交给本地存储合并，再保存新的游标。
- 接着客户端读取本机待上传队列，优先把记录分批提交；较新的服务器支持批量接口，旧服务返回 404 或 405 时，客户端会退回逐条接口。
- 服务端每条写入带预期修订号和请求编号：修订号用于判断两边是否基于同一版本，请求编号用于识别重试请求。
## 4. 冲突处理：按字段合并｜常被问

冲突按字段合并。 **一句话层。**

比如本机把计划日期改到更晚，另一台把计划标题改了；合并后，日期字段保留本机未上传的值，标题字段采用远端值，两端修改都留下。 如果两台都改同一个字段，就比较字段更新时间；本机和远端的版本信息包含时间与设备编号，时间相同再按设备编号作稳定排序，并提示用户哪份计划的哪些字段各自保留。 **三句话层。**

计划、知识点等结构记录按字段版本合并；课堂位置则作为一个完整状态字段比较，避免把一台设备的新课堂和另一台设备的旧测验拼成不一致的场景。进度类记录按事件追加、按 ID 去重；例如答题记录不会因为收到远端副本就再记一遍。 **深一层。**

像两间分馆各自给账目字段盖上“谁在何时改过”的小印章：没传出去的本地改动先留着，其余字段接收另一间馆的版本；同一个字段都动过，就按印章决定，并告诉读者发生了合并。比喻里的印章对应真实的字段版本元数据；两台电脑时钟差很大时，按时间判断谁后改可能出错，这是记录过的局限。

### 离线改了计划，另一台的新版本会不会把它盖掉？

- 比如本机把计划日期改到更晚，另一台把计划标题改了；合并后，日期字段保留本机未上传的值，标题字段采用远端值，两端修改都留下。
- 如果两台都改同一个字段，就比较字段更新时间；本机和远端的版本信息包含时间与设备编号，时间相同再按设备编号作稳定排序，并提示用户哪份计划的哪些字段各自保留。
- 两台电脑时钟差很大时，按时间判断谁后改可能出错，这是记录过的局限。
## 5. 失败恢复与单设备在线边界｜偶尔问

同步失败先留在本机。 **一句话层。**

每轮遇到可重试的网络问题时，客户端会对同一请求再试一次；整轮仍失败，就按 30 秒起步、逐步增加到最多 5 分钟的间隔重试。 上传成功的记录先保存游标，再清除相应的待上传标记；如果进程中断，确定性的请求编号让下一轮能安全重放，仍未确认的本地记录不会因为网络故障被删掉。 **三句话层。**

客户端服务登录后启动同步服务，关闭或退出账号时停止任务；同一个账号目前限定一台设备在线，新设备登录会撤销旧设备会话，旧设备未同步的进度仍留在本机，下次登录再补传。 **深一层。**

这像快递暂时走不通时，包裹仍留在分馆柜台，系统过一会儿再送；但同一张读者卡一次只能有一间分馆保持在线，换馆登录会让旧馆停止在线。它不是“多台同时编辑也实时锁住”的协作系统；离线编辑仍可保留并在下次登录后合并。

### 断网或软件重开后，本机还没同步的修改怎么办？

- 每轮遇到可重试的网络问题时，客户端会对同一请求再试一次；整轮仍失败，就按 30 秒起步、逐步增加到最多 5 分钟的间隔重试。
- 上传成功的记录先保存游标，再清除相应的待上传标记；如果进程中断，确定性的请求编号让下一轮能安全重放，仍未确认的本地记录不会因为网络故障被删掉。
- 客户端服务登录后启动同步服务，关闭或退出账号时停止任务；同一个账号目前限定一台设备在线，新设备登录会撤销旧设备会话，旧设备未同步的进度仍留在本机，下次登录再补传。
## 学习路线：不用背｜基本不问

记住“先拉远端变化，再上传本机待传；字段级合并；失败保留并重试；同账号一次一台在线”就够了；接口路径、请求字段全集和游标内部格式只需知道代码在哪查。
