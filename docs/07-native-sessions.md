# 模块08｜原生会话：短期访问凭证与可轮换续期凭证

> **Q12｜深度：能讲清原理**

## 前置概念

**会话**是一次登录建立起来、服务器能持续识别并撤销的一组状态。**access token**用于日常API请求，**refresh token**用于access到期时申请下一组凭证。前者寿命短，减小单个访问凭证暴露后的可用时间；后者能续期，因此必须更谨慎地保管、轮换和撤销。这里说的是MentorFlow的原生会话实现，不把内部令牌格式当成通用标准。

## 自然讲解

可以把access想成当日通行卡，把refresh想成换发通行卡的凭条。普通业务请求带access；它在本项目里最多有效300秒。接近过期时，客户端把refresh交给服务端，服务端校验它所属的会话族，再发新的access和新的refresh，同时把旧refresh的摘要记为已使用。之后只能拿新refresh继续续期，避免同一张旧凭条被反复兑换。

这个“换新并作废旧凭条”解决正常续期，也给重放检测提供依据：如果旧refresh再次出现，服务发现它已不是当前refresh，或在已使用摘要中，便撤销整个会话族并拒绝续期。两次续期如果拿同一个旧refresh并发到达，代码也会检测到正在处理的摘要并撤销对应会话族；提交前还会在事务里重新核对当前摘要，避免竞争的请求都成功换发。这里讲的是refresh重放处理，不代表系统能识别所有被复制的access使用。

另一条规则是单设备在线：同一账号在新设备完成登录时，服务器先把该主体已有的活动会话族标记为被新会话替代，再保存新的会话族。因此旧设备之后刷新会话会收到“已在另一台设备登录”一类结果；项目需求也明确要求新设备登录挤下旧设备。客户端收到会话被替代的状态后停止继续课堂并提示用户。

所以可以把整条因果说成：access承担短时访问，refresh承担续期；续期时刷新两者并登记旧refresh，顺序或并发重复使用旧refresh都会撤销会话族；新设备登录则撤销旧会话族，保证同账号同一时间只保留一台在线。它不是“access永不过期、refresh只是备用密码”，也不需要在首答里展开随机数或摘要算法细节。

## 可直接口述

“MentorFlow把原生登录会话分成短期access和用于续期的refresh。access最多五分钟；refresh使用时会换发新的access与refresh，并把旧refresh记为已用。旧refresh无论之后再次使用，还是在前一次续期尚未结束时并发重放，都会被识别并撤销整个会话族。同一账号在新设备登录时，服务器也会撤销旧会话族，让旧设备下线。这分别处理了短凭证暴露、refresh重复使用和多设备并行登录的问题。”

### 原生会话怎样续期并处理refresh重放与另一设备登录？

- access用于短时API访问，refresh续期；本项目access有效期最多300秒。
- 续期轮换refresh并记录旧摘要；旧refresh顺序重放或在续期中并发重放都会撤销会话族。
- 同账号新设备登录会撤销旧活动会话族，使旧设备会话失效。

### 追问加练

追问：检测到旧refresh重放时，为什么撤销整组会话？

答法：服务器无法仅凭重放请求分辨旧令牌是被盗副本还是迟到请求，因此按会话族撤销，避免继续依赖可能泄露的续期链。
