# 从零到一：一步步搭起现在的 MentorFlow

MentorFlow 把按资料学习接成一条路。

用户做 MentorFlow，是为了方便用 AI 学习项目上要用的知识。最初试过以学习奖励驱动的“学习远征”，后来决定专注学习功能；2026-09-29，旧代码的问题集中出现，用户决定推倒重来。现在这套系统围绕“依据资料学准”连接计划、课堂和进度。

先把它想成一间自习室：桌面是学习入口，本机记录本保存进度，远处的服务台办理账号、同步和资料检索。每站只借这个场景说明职责；软件里没有真实房间，程序之间靠接口和网络传数据。

文件开头的“常被问／偶尔问／基本不问”是针对 Java + AI 副项目的学习优先级，不是面试频率统计。每站先讲一句话层，再讲三句话层，最后给口述稿；深挖请读对应专题。事实基线：提交 `e61fd00d`，项目状态截至 2026-10-18。

## 第一站：先搭桌面窗口｜偶尔问

窗口把学习功能放在一处。**一句话层。**

MentorFlow 是 Windows 桌面程序，PySide6 建立桌面窗口，Qt WebEngine 显示 React 页面；页面经 QWebChannel 把操作交给 Python 本机程序。本机程序管学习流程，界面负责呈现和交互；用户点“开始上课”时，页面通过本机桥提交请求，由本机程序检查当前阶段并保存结果；网页不直接改课程数据库。桥像前台传话口，只递交请求，不拥有账本。**三句话层。**

**你可以这样跟面试官说：**“它是 Windows 桌面学习软件：PySide6 和 Qt WebEngine 承载 React 界面，页面通过桥调用 Python 本机程序。界面展示操作，本机程序处理流程和本地数据。”

### 页面怎样把操作交给程序？

- 参考要点：PySide6 建立桌面窗口，Qt WebEngine 显示 React 页面。
- 参考要点：页面经 QWebChannel 把操作交给 Python 本机程序。
- 参考要点：本机程序管学习流程，界面负责呈现和交互。
## 第二站：先在本机记账｜常被问

学习进度先保存在本机。**一句话层。**

课程数据保存在本机 SQLite 的 `course.sqlite3`；课堂与计划的变化由 Python 本机程序写入。SQLite 使用 WAL 模式记录变更，计划进度与学习记录因此有本地落点。账号跨设备接续是后面单独的同步链。像每间自习室先有自己的登记簿，但这个比喻不表示只拷贝一个数据库文件就完成了安全备份。**三句话层。**

**你可以这样跟面试官说：**“学习数据先落在本机 SQLite。本机程序按学习流程写入，WAL 记录数据库变更；账号跨设备接续是后面单独的同步链。”

### 本地账本负责什么？

- 参考要点：课程数据保存在本机 SQLite 的 `course.sqlite3`。
- 参考要点：课堂与计划的变化由 Python 本机程序写入。
- 参考要点：账号跨设备接续是后面单独的同步链。
## 第三站：从学习需求走到知识地图｜常被问

目标和资料决定计划内容。**一句话层。**

用户说明学习目标并提供资料，系统整理计划结构；用户确认后，程序依据资料目录生成知识点和导航，再形成学习地图。新版目录切点结构已经合入代码，但当前状态记录为尚未发布。像管理员按讲义目录摆好学习桌，但目录不是老师，也不会替用户确认学习目标。**三句话层。**

**你可以这样跟面试官说：**“用户先给目标和资料，系统整理方案，用户确认后再按资料目录生成知识点和学习地图。新版切点结构已合入，但当时还没有随版本发布。”

### 谁决定计划进入下一步？

- 参考要点：用户说明学习目标并提供资料。
- 参考要点：用户确认后，程序依据资料目录生成知识点和导航。
- 参考要点：新版目录切点结构已经合入代码，但当前状态记录为尚未发布。
## 第四站：老师上课，程序判题｜常被问

老师讲课，程序负责流程。**一句话层。**

本机流程控制程序（状态机）依据已确认计划推进课堂；AI 老师按原文讲解和互动，程序保存课堂进度。模型不能直接替系统改计划或账本。检测里客观题由程序判分，问答题由用户先作答，再对照原文要点自行判对错；允许按部分要点自评，AI 不判主观题。像老师带读讲义、管理员登记出勤；生活中的老师能临场判断，软件里的模型不能直接替系统改计划或账本。**三句话层。**

**你可以这样跟面试官说：**“课堂流程由本机流程控制程序（状态机）控制，AI 老师围绕资料讲解；客观题由程序判分，简答题由用户对照原文自检。模型参与教学，但学习状态仍由程序管理。”

### 为什么模型不能直接改学习状态？

- 参考要点：本机流程控制程序（状态机）依据已确认计划推进课堂；AI 老师按原文讲解和互动，程序保存课堂进度。
- 参考要点：程序保存课堂进度。
- 参考要点：模型不能直接替系统改计划或账本。
## 第五站：账号需要服务器｜常被问

账号服务先核验登录身份。**一句话层。**

客户端主要仍是 Python，服务器业务当前由 Java + Spring Boot 承担；Keycloak 管身份，服务器业务处理账号与同步接口。Java 服务于 2026-10-16 正式切流，旧 Python 服务停流量并保留回退。像自习室有门禁和总服务台；进门身份验证不等于自动能看所有档案，也不代表注册每条路径都已真人验收。**三句话层。**

**你可以这样跟面试官说：**“客户端仍以 Python 为主，在线业务由 Java 服务处理，身份由 Keycloak 管理。Java 已正式承接流量，旧服务还保留回退；注册流程的验证边界要按项目记录准确说明。”

### 登录身份和业务权限各管什么？

- 参考要点：Keycloak 管身份，服务器业务处理账号与同步接口。
- 参考要点：身份验证不等于自动能看所有档案。
- 参考要点：旧 Python 服务停流量并保留回退。
## 第六站：多台设备接续学习｜常被问

同步让别的电脑接上进度。**一句话层。**

学习变化先写入本地待同步队列，登录和定时同步时再与服务器交换账号记录；失败项目留在队列等待重试。客户端 CourseStore.apply_remote 接收远端记录，并将其与尚未同步的本地改动按字段合并，避免把整份新旧数据盲目覆盖。像两家分馆交接借阅登记，但原始上传文件留在本机，服务器同步记录不等于备份原件。**三句话层。**

**你可以这样跟面试官说：**“客户端先保存本地变化，再把账号记录放进待同步队列；同步失败会保留待处理项。客户端接收远端记录时按字段合并尚未同步的本地改动，用户上传的原始文件不随账号同步。”

### 同步为什么不等于备份？

- 参考要点：学习变化先写入本地待同步队列。
- 参考要点：客户端 CourseStore.apply_remote 接收远端记录，并将其与尚未同步的本地改动按字段合并。
- 参考要点：原始上传文件留在本机，服务器同步记录不等于备份原件。
## 第七站：装好软件，再练习更新｜偶尔问

安装包把程序送到用户电脑，更新器让旧版本接上新版本。**一句话层。**

项目用安装程序交付 Windows 软件，更新流程会下载更新、验签、替换文件并处理失败恢复；日常发布默认走增量文件。签名用于验证来源和完整性，不是加密。像装门和核验封条；装好一次不代表旧版本升级、失败恢复都已排练。项目要求用真打包程序排练旧版到新版的过程。**三句话层。**

**你可以这样跟面试官说：**“安装和软件内更新是两条需要实测的交付环节。更新器会下载、验签、替换并处理失败恢复；我们用真打包程序排练旧版到新版的过程。”

### 为什么真打包后还要排练旧版更新？

- 参考要点：更新流程会下载更新、验签、替换文件并处理失败恢复。
- 参考要点：签名用于验证来源和完整性，不是加密。
- 参考要点：用真打包程序排练旧版到新版的过程。
## 第八站：资料问答先找原文｜常被问

先找原文，再由模型回答。**一句话层。**

客户端抽取本地资料文字并发送文本块，Java 服务按问题查找相关片段，客户端再用用户选择的模型生成回答。服务器保存文本索引而不接管原文件；引用可以回到资料片段核对。像资料室跑腿员找到几页讲义交给老师，但相似段落不保证答案完整或正确。**三句话层。**

**你可以这样跟面试官说：**“RAG 把找资料和写回答分开：客户端抽取文字，服务器检索相关片段，客户端再调用模型组织答案。引用帮助回看原文，但检索命中不等于回答正确。”

### 找到资料为什么不等于答对？

- 参考要点：客户端抽取本地资料文字并发送文本块。
- 参考要点：Java 服务按问题查找相关片段，客户端再用用户选择的模型生成回答。
- 参考要点：相似段落不保证答案完整或正确。
## 第九站：开发时怎样分工与核对｜偶尔问

任务写清边界，回执交代结果。**一句话层。**

项目协作先写清需求、允许修改的文件和验收方式，实现者按边界完成工作，再用回执说明改动和验证证据。架构师负责核对和集成；安装、更新等关键交付还要用真打包程序排练，代码看起来正常不等于用户已验收。像自习室管理员把维修任务写清，再检查交付结果；这不表示实现者可以自行决定产品方向。口述自己的贡献时，应如实区分需求决定、AI 实现和本人验证，不能把 AI 生成的代码说成亲手逐行编写。**三句话层。**

**你可以这样跟面试官说：**“协作时先把需求、修改范围和验收方式写清，实现者交回改动与验证证据，再核对集成。我会说明自己实际做的需求决定和验证，不把 AI 生成的代码说成亲手逐行写的；安装更新这类交付还要真包排练。”

### 回执怎样帮助检查 AI 协作结果？

- 参考要点：项目协作先写清需求、允许修改的文件和验收方式。
- 参考要点：实现者按边界完成工作，再用回执说明改动和验证证据。
- 参考要点：口述自己的贡献时，应如实区分需求决定、AI 实现和本人验证。
