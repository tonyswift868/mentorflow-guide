# 07｜账号与登录：谁认得你，谁让你进门

本篇事实基线：代码提交 `e61fd00d`。标题里的“常被问／偶尔问／基本不问”是复习优先级判断，不是面试统计。贯穿场景是一栋有前台的公寓：Keycloak 像核验住户身份的发证处，Java 服务像每间房门口的门卫，PostgreSQL 像住户与门禁记录的账本。这个比喻能解释“身份核验、接口授权、持久化状态”分工；它不等于真实的物理门锁，令牌和数据库事务也不是一张实体门卡。

## 1. 注册：先登记，再确认邮箱｜偶尔问

注册先核验邮箱。 **一句话层。**

在 MentorFlow 的桌面软件里，用户填账号名、邮箱和密码；Java 账号服务检查输入，再把注册开始请求交给 Keycloak 的身份扩展。Keycloak 建立待验证账号并发出邮箱验证码，用户在软件里填码，验证成功后才可以登录。 **三句话层。**

这条链路由 Java 的 `LifecycleController146` 接收注册和验证码请求，`LifecycleService146` 组织流程，`NativeIdentityBridge` 把身份操作送到 Keycloak；验证码的一次性状态和用户凭据由 Keycloak 扩展维护。 当前项目状态记录：注册代码已上线，但还没有真人完整走通线上注册；不能把代码接线说成真实用户验收。 **深一层。**

像公寓前台先录入入住申请，再由发证处确认申请人能收到通知。这个比喻说明了“登记”和“验证”是两步；真实系统不会因为填了邮箱就把邮箱持有人自动认定为账号本人，验证要由验证码流程完成。

### 注册时，Java 和 Keycloak 各做什么？

- Java 账号服务检查输入，再把注册开始请求交给 Keycloak 的身份扩展。
- Keycloak 建立待验证账号并发出邮箱验证码，用户在软件里填码，验证成功后才可以登录。
- 验证码的一次性状态和用户凭据由 Keycloak 扩展维护。
- 当前项目状态记录：注册代码已上线，但还没有真人完整走通线上注册；不能把代码接线说成真实用户验收。
## 2. 登录与令牌：短期通行证，长期可续｜常被问

登录后拿到短期访问令牌和可轮换的刷新令牌。 **一句话层。**

桌面把账号密码发给 Java 的原生登录接口，Java 通过私有 HTTPS 身份桥让 Keycloak 执行密码核验；身份通过后，Java 建立自己的原生会话族并返回 access 与 refresh。日常桌面请求使用随机格式的原生 access；它不是 Keycloak JWT，服务器不会把它按 JWT 解码。 **三句话层。**

Spring Security 的统一入口会按令牌类型走不同验证：Keycloak JWT 由资源服务器验证签名和声明；原生 access 交给 `NativeSessionService` 检查进程缓存与数据库中的会话族。原生 access 有效期为 300 秒，刷新后会轮换 refresh；数据库保存刷新令牌摘要和会话主体，不保存刷新令牌明文。默认 TTL=0 时会话族没有时间到期，用户退出或明确撤销仍会使它失效；一台设备登录会撤销同账号先前的会话族。 **深一层。**

把 access 想成当天的访客通行证，把 refresh 想成前台核验后换新证的凭条。这个比喻能说明短期 access 与续接会话分工；但 refresh 不是能独立开门的永久密码，服务端会检查它是否当前有效、是否已被使用，旧 refresh 被重放会撤销整组会话。

### Keycloak JWT 和桌面原生令牌有什么区别？

- Spring Security 的统一入口会按令牌类型走不同验证：Keycloak JWT 由资源服务器验证签名和声明；原生 access 交给 `NativeSessionService` 检查进程缓存与数据库中的会话族。
- 原生 access 有效期为 300 秒，刷新后会轮换 refresh；数据库保存刷新令牌摘要和会话主体，不保存刷新令牌明文。
- 默认 TTL=0 时会话族没有时间到期，用户退出或明确撤销仍会使它失效；一台设备登录会撤销同账号先前的会话族。
## 3. 找回密码与改密：证明邮箱或当前身份，再换凭据｜偶尔问

邮箱验证后重置密码，旧会话随之撤销。 **一句话层。**

找回入口先向邮箱发送验证码，再校验验证码并签发短期重置证明；用户提交新密码和确认密码后，Keycloak 更新凭据，Java 收到完成结果后撤销该账号现有原生会话。客户端随后提示用户用新密码登录。 **三句话层。**

为了不泄露邮箱是否注册，找回请求对“邮箱存在”和“不存在”使用相同的对外提示。改密码则要求当前用户已登录，并重新核验当前密码；验证通过后更新密码并撤销该主体的会话。邮箱修改也使用登录态下的验证码步骤。 **深一层。**

这像住户遗失钥匙时，先用登记的联系方式证明自己，再由前台换新钥匙并作废旧门禁。它说明了重置证明与旧会话撤销的目的；实际系统里验证码、密码凭据和会话状态分别由 Keycloak、Java 与 PostgreSQL 配合处理，不是一把钥匙由单一组件全部保管。

### 找回密码与改密有哪些步骤和边界？

- 找回入口先向邮箱发送验证码，再校验验证码并签发短期重置证明；用户提交新密码和确认密码后，Keycloak 更新凭据，Java 收到完成结果后撤销该账号现有原生会话。
- 为了不泄露邮箱是否注册，找回请求对“邮箱存在”和“不存在”使用相同的对外提示。
- 改密码则要求当前用户已登录，并重新核验当前密码；验证通过后更新密码并撤销该主体的会话。
- 邮箱修改也使用登录态下的验证码步骤。
## 4. 注销：跨系统分步完成，失败时从检查点继续｜偶尔问

注销分步清理账号数据和身份，并撤销会话。 **一句话层。**

用户先提交当前密码准备注销，服务返回操作编号和恢复凭证，但此时还没删账号；用户明确确认后提交第二步。流程撤销会话、清理 PostgreSQL 中该账号的业务数据、让 Keycloak 删除对应身份，最后再确认注销完成。服务器不通过网络删除客户端文件；客户端收到注销完成确认后，清理该账号的本机受管数据，并从本机操作系统的凭据库删除绑定的模型凭据。用户选定的外部原件和其他账号不在清理范围。 **三句话层。**

PostgreSQL 和 Keycloak 是两个独立系统，无法由一个 JDBC 事务同时提交或回滚。服务把操作状态和检查点持久化；如果数据库清理已完成、Keycloak 删除暂时失败，操作会保持可重试状态，原恢复凭证可继续同一操作。因而失败恢复不等于“所有内容都回到删除前”。 **深一层。**

这像退租：前台先登记退租单，再清理门禁和房间账目，最后通知发证处注销住户身份。这个比喻能说明步骤与检查点；但现实里的两个系统没有一个共同的“撤销全部”按钮，所以恢复靠记录进度后续做，不是跨系统原子回滚。

### 为什么注销不能简单包进一个数据库事务？

- 注销分步清理账号数据和身份，并撤销会话。
- 用户先提交当前密码准备注销，服务返回操作编号和恢复凭证，但此时还没删账号；用户明确确认后提交第二步。
- PostgreSQL 和 Keycloak 是两个独立系统，无法由一个 JDBC 事务同时提交或回滚。
- 服务把操作状态和检查点持久化；如果数据库清理已完成、Keycloak 删除暂时失败，操作会保持可重试状态，原恢复凭证可继续同一操作。
## 5. Spring Boot 的门卫、数据库账本与迁移权限｜常被问

Spring Boot 承接账号业务，Spring Security 统一认证请求。 **一句话层。**

Keycloak 主要负责用户身份、密码和邮箱验证码；Java 服务负责 HTTP 接口、请求认证与授权、账号业务流程和数据库事务。验证令牌后，服务还要检查账号是否开放、用户是否属于请求的组织或工作区；令牌有效本身不代表有权读取任意空间。 Keycloak JWT 由资源服务器验证签名和声明；原生 access 则由 `NativeSessionService` 按会话族检查。 **三句话层。**

业务持久层使用 Spring JDBC 和事务模板延续现有 SQL 与边界，数据库用行级安全（RLS）按事务绑定的账号/租户范围限制行访问。Alembic 迁移仍由专门迁移角色执行，Java 不在启动时自动建表。BUG-107 暴露过线上权限与测试夹具不一致：迁移角色对 `account_closure` 只有 `USAGE`、没有 `CREATE`，所以替换注销函数时报权限错误；修复是在替换函数时临时 `SET LOCAL ROLE mentorflow_closure`，没有给迁移角色额外授权。上线脚本后来逐步检查退出码，避免失败被管道吞掉。 **深一层。**

这次把服务器适合的账号和同步业务迁到 Java，原因是用户的求职方向是 Java + AI；模型提示与课堂编排仍留在 Python。选择依据是岗位方向和业务分工，不是“Java 一定比 Python 快”的性能结论。

在公寓比喻里，Spring Security 像门口先看通行证，业务权限像核对住户是否属于这栋楼和这间房，RLS 像每个账本抽屉只允许当前楼层管理员打开。它能帮助理解多层边界；但 RLS 不是认证系统，也不能代替应用层身份和成员关系校验。

### 账号请求的认证、授权、数据库访问和迁移各管什么？

- Keycloak JWT 由资源服务器验证签名和声明；原生 access 则由 `NativeSessionService` 按会话族检查。
- 验证令牌后，服务还要检查账号是否开放、用户是否属于请求的组织或工作区；令牌有效本身不代表有权读取任意空间。
- 业务持久层使用 Spring JDBC 和事务模板延续现有 SQL 与边界，数据库用行级安全（RLS）按事务绑定的账号/租户范围限制行访问。
