# 模块04｜资料问答的RAG完整链路

**Q08｜资料问答的RAG链路怎样工作？**  
**深度：必须能背**

## 先知道RAG解决什么问题

RAG可以理解成“先找资料，再带着资料回答”。用户的文件可能很长，直接把整本文件交给模型既不适合逐题检索，也难指出答案依据。系统先把可读内容整理成段落，提问时找出相关段落，再让模型围绕这些段落组织回答。

## 从文件到带出处的回答

以一份二十页的操作手册为例。用户选择文件后，客户端在本机抽取文本，并保留页码或章节等位置信息；抽出的内容切成较小段落，在本机登记后分批上传文字片段。服务器为片段计算向量并保存，等完整段落都到齐后才把文档标为可检索。这里处理的是抽取后的文本片段，不能把流程说成原文件整份上传。

用户问“重置密码后为什么还要重新登录？”时，客户端把问题、所选资料范围和返回数量发到服务器。服务器把问题转成向量，在指定账号和文档范围内检索候选段落，排序后返回前几段原文、页码和章节。客户端把问题、历史问答及这些段落组织成模型输入，由用户配置的模型生成回答；应用保存问答，并显示资料出处，方便用户回查。

可以把它想成先从一本手册里找几张相关索引卡，再让老师只依据这些卡片回答。索引卡找得相关，仍不保证回答一定正确；如果资料缺页、抽取错了，或检索段落没覆盖关键条件，回答也可能偏题。因此RAG提供的是可追溯的依据链，而非正确率保证。

## 可以直接说

“RAG先在本机抽取文件文本并切段，再把文本片段传到服务器建立检索数据。提问时服务器在选定资料中找相近原文并返回段落及位置，客户端连同问题和历史交给模型组织回答，最后保存问答并展示出处。检索到依据不代表答案必然正确，还要核对引用原文。”

### 资料问答的RAG链路怎样工作？

- 客户端抽取用户文件文字并切段，上传文本片段供服务器处理。
- 服务器计算并保存片段向量，完整后标记可检索；收到问题后在选定资料中检索，返回原文与位置。
- 客户端把问题、历史和检索段落交给模型组织答案，并保存和展示出处。

### 追问加练

面试官可能追问：检索到正确片段，答案就一定可靠了吗？  
一句答法：不一定，模型仍可能误读或漏掉条件，所以要查看回答引用的原文。
